# Maintaining Déjà-vu Town

The profile is a floating isometric island drawn from public GitHub data. Every featured project is a building, and the drawing *is* the data:

| What you see | What it means |
| :--- | :--- |
| Building height | Default-branch commits, log-scaled relative to the other buildings |
| Flag on the roof | At least one published release |
| Stars in the night sky (dark theme) | One per GitHub star across the indexed repositories (capped at 900) |
| The tram looping the island | Nothing — it is a déjà vu. It just keeps coming round. |

GitHub's **light theme is daytime** (sun, clouds, birds) and its **dark theme is night** (moon, lit windows, fireflies, shooting stars, glowing crystals). All of it is original SVG generated by this repository: no third-party stats service, no remote fonts or images, no scripts. Motion is SMIL animation, which browsers play inside `<img>`.

## Buildings

Each featured project is assigned a building in [the configuration](<../profile.config.json>) under `buildings`. Unlisted projects get a plain house.

| Kind | Drawing | Used for |
| :--- | :--- | :--- |
| `cafe` | Corner café with an awning; speech bubbles keep popping up | Ecoku (comments) |
| `radio` | Lattice broadcast tower sending out sound waves | edgeTTS (speech) |
| `balloon` | Smiling hot-air balloon with two small friends | Smoji (emoji) |
| `post` | Post office; paper planes fly off the roof | sani (short links) |
| `studio` | Photo workshop with a giant lens that flashes, and a chimney | PicForge (images) |
| `lighthouse` | Lighthouse with a sweeping beam and a heartbeat status light | romi (monitoring) |
| `press` | Type foundry whose billboard cycles 字 · Aa · あ · 한 | webfont-slice (fonts) |
| `bucket` | A water tower that is literally a bucket labelled S3 | Pail (S3 storage) |
| `house` | Gabled house | anything else |

The clock tower in the middle stands for this profile itself. Tallest buildings take the back plots so nothing hides behind them; the island has **8 plots**, so `project_count` may be at most 8.

## Files

- [README](<../README.md>): handwritten navigation, section intros and PGP identity, plus four generated regions (`PROFILE-HERO`, `PROJECTS`, `BLOG-POST-LIST`, `FOOTER`).
- [Configuration](<../profile.config.json>): owner, feed, counts, exclusions, the curated `featured` list, `buildings`, and reviewed one-line `descriptions`.
- [Updater](<../scripts/update_profile.py>): GitHub GraphQL collection, RSS parsing, selection and deterministic rendering. Python 3.11+, **standard library only**.
- [Isometric kit](<../scripts/iso.py>): projection, colour/night tinting, solids (boxes, cylinders, roofs) and SMIL helpers.
- [Town](<../scripts/town.py>): the island, buildings, tram, sky, labels.
- [Artwork](<../scripts/profile_art.py>): hero, project cards, *The Dejavu Times*, footer, and the `<picture>` markup.
- [Preview](<../scripts/preview.py>): renders the README through GitHub's own Markdown API into `.preview/site/`.
- [Public snapshot](<../data/profile.json>) and [generated assets](<../assets/generated/>).
- [Tests](<../tests/test_profile.py>): network-free.
- [Workflow](<../.github/workflows/profile.yml>): the single writer of the README and generated assets.

## CI/CD

The workflow has two jobs.

**Test & preview** runs on every relevant push and pull request: compile, unit tests, (on PRs) a byte-exact check that the committed artwork matches its sources, an offline render, and a preview built with GitHub's Markdown API. The preview — `light.html`, `dark.html` and an artwork `gallery.html` — is uploaded as the **profile-preview** artifact, so a design change can be reviewed before it reaches the profile.

**Rebuild the town** runs after the tests pass, on `master` only, never for pull requests or forks:

| Trigger | What runs | UTC | UTC+8 |
| :--- | :--- | :--- | :--- |
| Schedule | Full rebuild: projects, artwork, newspaper | 00:23 daily | 08:23 |
| Schedule | Newspaper only (keeps the dated GitHub snapshot) | 06:23, 12:23, 18:23 | 14:23, 20:23, 02:23 |
| Push to `master` touching sources | Full rebuild | — | — |
| **Actions → Déjà-vu Town → Run workflow** | `full`, `blog-only`, or `offline` (re-render the committed snapshot) | — | — |

Each run writes a summary to the run page: the buildings with their heights and metrics, the star count, the latest post, and the files that changed. It then verifies the exact file inventory, commits only if something changed, and pushes without force; a concurrent human push makes it fail safely until the next run. Runs on `master` are serialized; PR previews cancel their stale predecessors.

The unrelated exchange-rate release workflow (`releaseRateJSON.yml`) is untouched.

No custom secret is required: `GH_TOKEN` is the job's built-in token, used to authenticate public API calls. Repository rules must let the bot push to `master`. Scheduled workflows can be paused by GitHub after long inactivity; use **Run workflow** to wake them.

## Selection

Eligible repositories belong to `DejavuMoe`, are public, non-fork, non-archived, have commit history, and are not excluded. The profile repository itself is excluded so automation commits and exchange-rate releases cannot inflate it.

The `featured` list is used first, in order, skipping anything no longer eligible. Remaining plots are filled by score:

```text
score = 0.35 × ln(1 + stars) + 0.45 × ln(1 + default-branch commits) + 0.20 × ln(1 + published releases)
```

The complete eligible index stays available as native text in the README's disclosure, with a 🏠 next to projects in the town.

- **Stars:** current `stargazerCount`.
- **Commits:** default-branch `history.totalCount`, **all authors**, not personal contributions.
- **Releases:** paginated default GraphQL connection, non-draft with a publication date; prereleases count, bare tags do not. Explicit `CREATED_AT` ordering is deliberately avoided (it returned historical Smoji releases the public endpoints did not).
- **Homepage:** the repository's website field, kept only if it is HTTPS, credential-free, on a default port and not github.com. Shown on cards and in the *Try them live* row.
- **Descriptions:** reviewed overrides in the configuration win over stale GitHub descriptions.
- **Post summaries:** the feed's `<description>`/`<summary>`, reduced to plain text and capped at 160 characters.

## Updating locally

```powershell
python scripts/update_profile.py              # full refresh (token from GH_TOKEN, GITHUB_TOKEN or `gh auth token`)
python scripts/update_profile.py --blog-only  # newspaper only
python scripts/update_profile.py --offline    # re-render the committed snapshot, no network
python scripts/update_profile.py --check      # verify bytes and file inventory, no writes
python -m unittest discover -s tests -v
python scripts/preview.py                     # .preview/site/{light,dark,gallery}.html
```

To try a new look, edit the artwork modules, run `--offline`, then open the preview. Rendering is byte-for-byte deterministic on Windows and Linux (seeded randomness, fixed number formatting), which is what lets `--check` work.

Linux validation from this Windows workstation:

```powershell
linux-task.ps1 -Mode build -Project 'D:\Forgejo\DejavuMoe' `
  -Command 'python3 -m unittest discover -s tests -v && python3 scripts/update_profile.py --check'
```

## Failure behaviour

- Everything is fetched, validated and rendered in memory **before** any file is written. A GitHub, RSS, XML, snapshot or marker failure leaves the previous profile in place.
- Transient HTTP errors retry three times with backoff; requests time out; responses are capped at 8 MB; feeds with DOCTYPE/ENTITY declarations or non-UTF-8 encodings are rejected. The token is only ever sent to the GraphQL endpoint and credential-bearing redirects are refused.
- Blog links must be HTTPS on the blog host under `/posts/`. Cached homepages and summaries are re-validated on every render.
- External text is escaped for Markdown, HTML attributes and SVG. Tests assert that generated SVGs contain no scripts, `foreignObject`, links, `@import`, remote `url()` or `https://`, and stay under 400 KB.
- Only the four marker regions are replaced; handwritten content stays as written.

## GitHub display constraints

GitHub strips CSS and scripts from README HTML, so everything decorative is an image. Each image has four variants: light/dark × wide/compact. GitHub's native `#gh-light-mode-only` / `#gh-dark-mode-only` link selectors choose the theme (explicit and automatic); each link wraps a width-only `<picture>` that swaps in the taller compact layout on phones. Compound colour-scheme media queries are avoided because GitHub's `themed-picture` script rewrites them and drops width conditions.

Every image carries a full `alt`; project numbers are also in the text index, and blog posts, navigation and identity remain real text and real links. Text inside the SVGs uses system font stacks (rounded sans, monospace, and a serif for the newspaper), so lettering varies slightly between operating systems by design. GitHub's image cache may delay a visible update after a run.
